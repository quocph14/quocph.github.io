## Introduction

In this walkthrough, I investigate a simulated website defacement incident using Splunk as part of a Security Operations Center (SOC) investigation.

The objective is to examine web traffic, identify suspicious scanning activity, investigate files associated with the incident, correlate network events with Windows Sysmon telemetry, and analyze authentication-related activity.

Throughout the investigation, I use Search Processing Language (SPL) queries to narrow the dataset, inspect relevant events, and support findings with observable evidence.

## Investigation Scenario

The investigation focuses on suspicious activity involving a web application. The available evidence includes HTTP requests, request headers, file-transfer activity, endpoint process telemetry, and password-related events.

The investigation follows a structured workflow:

1. Identify suspicious web scanning activity.
2. Determine the vulnerability scanner and web application technology.
3. Trace the defacement-related filename and associated network activity.
4. Investigate a suspicious executable using Sysmon.
5. Examine a potentially related malware sample using VirusTotal.
6. Analyze repeated password attempts and calculate statistics.

The investigation uses the Boss of the SOC (BOTS) dataset in Splunk. Findings should be validated against the underlying events before being treated as confirmed indicators of compromise.

## Step 1: Identifying Suspicious Web Scanning Activity

First, search for events mentioning the target website:


This broad search provides an initial overview of the available evidence.

Next, group HTTP events by source IP address:

```spl
index=botsv1 imreallynotbatman.com sourcetype=http
```

## Step 4: Investigating the Suspicious Executable

The investigation identifies an executable named `3791.exe`. The next step is to determine whether the file was executed and whether endpoint telemetry provides evidence of its behavior.

Inspect the relevant Sysmon process-creation events and review fields such as:

- `Image`: the executable associated with the process event.
- `CommandLine`: the command used to start the process.
- `ParentImage`: the parent process that launched it.
- `Hashes`: the file hashes recorded by Sysmon, when available.
- `UtcTime`: the event timestamp in UTC.

A useful starting query is:

```spl
index=botsv1 sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
| search Image="*\\3791.exe"
| table _time Computer User Image CommandLine ParentImage Hashes
```

The exact sourcetype and field names may differ depending on how the Windows events were ingested into Splunk. If the query returns no results, inspect the available Sysmon sourcetypes and search for `3791.exe` across the relevant index.

## Step 6: Analyzing Password Attempts

To investigate authentication-related activity, filter HTTP POST requests using the relevant destination address and URI.

```spl
index=botsv1 sourcetype=stream:http dest_ip="<TARGET_IP>" http_method=POST
| stats count by src_ip formdata uri
| sort - count
```

Replace `<TARGET_IP>` with the destination IP address verified in the dataset. Confirm that the field names match the events available in your Splunk environment.

Compare timestamps and submitted values to determine the order of attempts and identify repeated values. If necessary, inspect individual events to establish whether the requests were directed at an authentication endpoint.

Repeated POST requests may indicate automated activity, but they do not independently prove that authentication succeeded.

Do not publish plaintext passwords, session tokens, or other authentication secrets in screenshots or report examples. Redact sensitive values before sharing the investigation publicly.

## Step 7: Calculating Password Statistics

The observed dataset contains 413 password entries and 412 distinct values. The calculated average password length is six characters.

These figures should be reproduced using the correct field and event filters before publication.

The following SPL query demonstrates how to calculate the total number of entries, distinct values, and average password length:

```spl
index=botsv1 sourcetype=stream:http
| eval password_length=len(password)
| stats count AS total_entries
        dc(password) AS distinct_values
        round(avg(password_length), 2) AS average_length
```

The field `password` is illustrative and must be replaced with the actual extracted field if the dataset uses another name.

Also, make sure the search is limited to the relevant authentication events. Running the query against all HTTP stream events could produce misleading statistics if unrelated requests are included.

## Conclusion

This investigation demonstrates how Splunk can support a structured analysis of suspicious web activity.

By examining HTTP request volumes, request metadata, file-transfer evidence, endpoint telemetry, and authentication-related events, an analyst can develop a clearer understanding of a potential website defacement incident.

The investigation also highlights the importance of validating each finding. A high request count does not independently prove exploitation, a filename does not confirm malicious behavior, and repeated password values do not establish successful authentication.

Combining network evidence, endpoint logs, and threat-intelligence information helps analysts develop evidence-based conclusions and identify opportunities to strengthen detection and prevention.

### Key Takeaways

- Use SPL to narrow large datasets and identify suspicious patterns.
- Correlate network events with endpoint telemetry to build a more complete timeline.
- Validate filenames and hashes before associating files with known malware.
- Distinguish suspicious authentication attempts from confirmed successful logins.
- Document the evidence and limitations behind every finding.

**Note:** This walkthrough uses a simulated investigation dataset for educational purposes. All indicators, hashes, and statistics should be verified against the original events before being used as confirmed findings.
